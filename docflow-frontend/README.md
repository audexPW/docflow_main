# DocFlow — фронтенд (сайт + мобильное приложение)

Личный кабинет и админка к бэкенду DocFlow: загрузка документов, проверка
распознанных реквизитов оператором, подтверждение и выгрузка в 1С, управление
пользователями и журнал действий.

Один код React/Vite работает и как сайт, и как мобильное приложение — мобильное
приложение это та же сборка, завёрнутая в нативную оболочку Capacitor (WebView
+ доступ к камере), как и предусмотрено в ТЗ.

## Что реализовано (по разделам ТЗ)

- Вход по логину/паролю, JWT в заголовке (§3, §7)
- Доступ по ролям: клиент видит только свои документы; оператор и админ — все;
  админ — пользователи и журнал (§7)
- Загрузка файлов JPG/PNG/HEIC/PDF, съёмка камерой, массовая загрузка
  нескольких файлов сразу (§3, §4)
- Оффлайн-накопление: без связи документы складываются на устройстве и
  досылаются автоматически при появлении сети (§3)
- Уведомления о смене статуса документа: распознан / ушёл в 1С / ошибка (§3)
- История документов со статусами и фильтром по статусу (§3, §4)
- Экран проверки: тип документа и реквизиты можно поправить перед отправкой
  в 1С; ручные правки помечаются (§5)
- Предпросмотр оригинала (картинка/PDF) и распознанный текст (§4, §5)
- Подтверждение → выгрузка в 1С, повторное распознавание (§5, §6)
- Тип документа не зашит: незнакомый тип/поле показываются как есть, оператор
  может добавить своё поле (§5)
- Админка: пользователи и журнал действий (§2, §7)

## Стек

React 18 + Vite 5, react-router. Без UI-библиотек и препроцессоров — обычный CSS.
Мобильная обёртка — Capacitor 6.

## Разработка

```bash
npm install
npm run dev
```

Дев-сервер поднимется на http://localhost:5173 и будет проксировать `/api`
на бэкенд `http://localhost:8080`. Другой адрес бэкенда:

```bash
BACKEND_URL=http://192.168.0.10:8080 npm run dev
```

## Сборка сайта

```bash
npm run build      # результат в dist/
```

### Деплой сайта через Docker

В комплекте `Dockerfile` (сборка + nginx) и `nginx.conf` (раздаёт статику,
проксирует `/api` на бэкенд).

```bash
docker build -t docflow-frontend .
docker run -p 80:80 docflow-frontend
```

Проще всего добавить фронтенд сервисом в `docker-compose.yml` бэкенда — тогда
имя `docflow-backend` из `nginx.conf` разрешится автоматически. Пример:

```yaml
  frontend:
    build: ./docflow-frontend
    ports:
      - "80:80"
    depends_on:
      - backend        # сервис бэкенда должен называться так же, как в nginx.conf
```

Если сервис бэкенда в compose называется иначе — поправьте `proxy_pass`
в `nginx.conf`.

## Мобильное приложение (Capacitor)

Приложение — обёртка над этой же сборкой. API отдаётся с сервера заказчика,
поэтому для мобильной сборки нужно указать его полный адрес.

```bash
# 1. адрес бэкенда для сборки
cp .env.example .env
#   в .env:  VITE_API_BASE_URL=https://docs.client.ru

# 2. собрать веб-часть
npm run build

# 3. поставить Capacitor и добавить платформы (один раз)
npm install
npx cap add android
npx cap add ios        # только на macOS с Xcode

# 4. синхронизировать сборку в нативные проекты
npx cap sync

# 5. открыть в Android Studio / Xcode для запуска и публикации
npx cap open android
npx cap open ios
```

Камера работает через системный выбор файлов с флагом захвата — этого
достаточно и в браузере телефона, и внутри WebView. Если понадобится полноценный
нативный плагин камеры, добавьте `@capacitor/camera` (уже в optionalDependencies)
и обработку в `src/pages/Upload.jsx`.

Требования ОС по ТЗ (iOS 14+, Android 8+) настраиваются в нативных проектах
после `cap add` (Deployment Target / minSdkVersion).

## Оффлайн-накопление

Реализовано на IndexedDB (`src/lib/offlineQueue.js`), работает и в вебе, и в
приложении, без дополнительных плагинов. Если при отправке нет связи, файлы
сохраняются на устройстве; в шапке показывается «Ожидают отправки: N», а на
странице загрузки — раздел «Ждут связи». Досылка происходит автоматически при
возврате сети, при возврате в приложение и раз в 30 секунд, плюс есть кнопка
«Отправить сейчас».

## Уведомления о статусе

`src/lib/notifications.js` + `src/components/NotificationWatcher.jsx`. Приложение
следит за статусами документов и уведомляет, когда документ распознан, ушёл в 1С
или произошла ошибка.

- В браузере — Web Notifications API.
- В приложении — нативный плагин локальных уведомлений. Для мобильной сборки
  установите его и синхронизируйте:

  ```bash
  npm install @capacitor/local-notifications
  npx cap sync
  ```

  Код обращается к плагину через глобальный `window.Capacitor.Plugins`, поэтому
  веб-сборка не зависит от него и не ломается, если плагин не установлен.

Это покрывает уведомления, пока приложение открыто или недавно свёрнуто.
Полноценный **push при полностью закрытом приложении** (когда сервер сам будит
телефон) — это отдельная история: нужен FCM/APNs (Firebase-проект и сертификаты
Apple), плагин `@capacitor/push-notifications`, endpoint на бэкенде для
регистрации токенов устройств и отправка уведомления при смене статуса на стороне
сервера. Клиентская проводка под это добавляется в тот же `notifications.js`.

## Структура

```
src/
  api.js              HTTP-клиент, токен, обработка ошибок
  auth.jsx            контекст авторизации
  config.js           адрес API
  App.jsx             маршруты и защита по ролям
  components/         Layout, StatusBadge, NotificationWatcher, OfflineBadge
  pages/              Login, Documents, DocumentDetail, Upload, Users, Audit
  lib/                подписи, форматирование, платформа, оффлайн-очередь, уведомления
```

## Заметки

- Токен хранится в localStorage; при 401 сессия сбрасывается и открывается вход.
- Пока документ распознаётся (`received`/`processing`), карточка сама
  обновляется раз в 3 секунды.
- Подписи типов документов, статусов и полей — в `src/lib/labels.js`.
  Новый тип или поле с бэкенда отобразятся даже без записи в этом файле.
